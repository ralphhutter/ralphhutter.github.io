Vor der Demo

So ist das Skript aufgebaut

Ein durchgehendes Beispiel: Notizen in ~/PersonalOS/Resources/ki-tools/ zusammenfassen. Zuerst mit einem Prompt, dann als Skill, dann als Subagent.

  1. Ausgangslage: Die Session ist ein Agent
  2. Skill: Prompt speichern und aufrufen
  3. Problem: Der Kontext füllt sich
  4. Subagent: anlegen und aufrufen
  5. Kombination: Subagent nutzt Skill
  6. Eingebaut: Explore, Plan, general-purpose
  7. Ausblick: Agent View, Workflows, AGENTS.md
  8. Merksatz: Skill = wie, Subagent = wer

Legende pro Folie

  • Zeigen: was auf dem Beamer zu sehen ist
  • Sagen: Stichworte für den Vortrag
  • Tippen: Eingabe im Terminal, schwarz hinterlegt
  • Terminal: was danach erscheint, sinngemäss. Die genaue Darstellung variiert je nach Version

Bedienung

  • Taste S blendet Zeigen und Sagen aus, wenn das Deck selbst projiziert wird
  • Orange Kante: vor dem Kurs testen

Die Session ist bereits ein Agent

Vor dem Kurs testen

  • Bezeichnungen und Reihenfolge der Kategorien in /context in der aktuellen Version ablesen und hier nachtragen

Zeigen

  • Terminal, danach /context als Raster
  • Auf die Zeile Messages zeigen

Sagen (Stichworte)

  • Jede Session ist schon ein Agent: Modell, Werkzeuge, Anweisungen, ein Ziel
  • Agent heisst: Claude arbeitet in Schleifen, liest, handelt, prüft
  • Alles, was die Session liest, landet in ihrem Kontextfenster
  • Das Kontextfenster ist begrenzt. Heute geht es darum, wie man es schlank hält
  • Wert bei Messages merken, wir kommen darauf zurück

Schritt 1 · Überblick

Wer arbeitet hier: Session, Subagents, Skills

Die Session ist der Agent im Haupt-Kontext. Subagents haben einen eigenen Kontext, Skills werden in einen Kontext geladen. Eigene Darstellung nach code.claude.com/docs/en/sub-agents, Farbweg HWZ-Shine.

Sagen (Stichworte)

  • Das ist das Bild, das am Ende der Demo steht
  • Blau: die Session, mit der wir sprechen
  • Grün: Subagents, je mit eigenem Kontextfenster
  • Hellblau: Skills, also Anleitungen, die in einen Kontext geladen werden
  • Subagents können selbst Subagents starten, bis drei Ebenen unter der Session
  • Wir bauen das Bild jetzt Schritt für Schritt nach

Schritt 2 · Skill

Der Auftrag als Prompt von Hand

Tippen

> Lies alle Notizen in Resources/ki-tools/ und fasse sie zusammen: pro Datei ein Satz, danach die drei wichtigsten Themen über alle Dateien. Speichere das Ergebnis als Resources/ki-tools/uebersicht.md.

Terminal, sinngemäss

Glob(Resources/ki-tools/*.md)
Read(Resources/ki-tools/2026-11-20_chatgpt.md)
Read(Resources/ki-tools/2026-11-20_claude.md)
...  30 Dateien
Write(Resources/ki-tools/uebersicht.md)
Do you want to create uebersicht.md?  1. Yes  2. ...

Vor dem Kurs testen

  • Ob Claude Code beim Schreiben nachfragt, hängt vom Permission Mode ab. Im Kurs mit den Einstellungen der Teilnehmenden durchspielen

Zeigen

  • Terminal, die Read-Zeilen laufen durch
  • Danach uebersicht.md in Obsidian öffnen

Sagen (Stichworte)

  • Ein guter Prompt, er funktioniert
  • Aber: Nächste Woche tippe ich ihn wieder, und formuliere ihn anders
  • Was sich wiederholt, gehört in einen Skill
  • Achtung auf die Zahl der Read-Zeilen. Jede Datei liegt jetzt im Kontext

Schritt 2 · Skill

Den Prompt als Skill speichern

Tippen

> Speichere diesen Ablauf als Skill zusammenfassen in .claude/skills/zusammenfassen/SKILL.md. Frontmatter mit name und description. Der Ordner kommt beim Aufruf mit. Ergebnis als uebersicht.md im selben Ordner speichern, wenn Schreiben erlaubt ist, sonst als Antwort zurückgeben.

Ergebnis: .claude/skills/zusammenfassen/SKILL.md

---
name: zusammenfassen
description: Fasst alle Notizen eines Ordners zu einer Übersicht zusammen. Einsetzen, wenn Notizen eines Ordners zusammengefasst werden sollen.
---

# Notizen zusammenfassen

Ordner: $ARGUMENTS

1. Lies alle Markdown-Dateien im Ordner.
2. Schreibe pro Datei einen Satz.
3. Nenne danach die drei wichtigsten Themen über alle Dateien.
4. Speichere das Ergebnis als uebersicht.md im selben Ordner.
   Darfst du nicht schreiben, gib es als Antwort zurück.

Zeigen

  • Die erzeugte Datei in Obsidian öffnen
  • Auf das Frontmatter zwischen den drei Strichen zeigen

Sagen (Stichworte)

  • Ein Skill ist ein Ordner mit einer Datei SKILL.md
  • name wird zum Befehl /zusammenfassen
  • description sagt Claude, wann der Skill passt. Der wichtigste Satz der Datei
  • Darunter die Anleitung in normaler Sprache
  • $ARGUMENTS ist ein Platzhalter für das, was beim Aufruf hinter dem Befehl steht
  • Agent Skills ist ein offener Standard, nicht nur Claude

Schritt 2 · Skill

Den Skill aufrufen

Tippen

> /clear
> /zusammenfassen Resources/ki-tools/

oder ohne Befehl, Claude erkennt die description

> Fasse die Notizen in Resources/ki-tools/ zusammen.

Terminal, sinngemäss

/zusammenfassen Resources/ki-tools/
Read(...)  30 Dateien
Write(Resources/ki-tools/uebersicht.md)

Vor dem Kurs testen

  • Wie der Skill-Aufruf im Terminal angezeigt wird (Zeile mit Skill-Name), in der aktuellen Version ablesen
  • Ob der neue Skill ohne Neustart im /-Menü erscheint. Falls nicht: /exit und claude neu starten
  • Ob der Prompt ohne Befehl den Skill zuverlässig auslöst

Zeigen

  • / tippen: der Skill erscheint im Menü
  • Ergebnis wie vorher, aber mit einem Wort ausgelöst

Sagen (Stichworte)

  • Gleiches Ergebnis, jedes Mal gleich gemacht
  • Zwei Wege: ich rufe ihn auf, oder Claude wählt ihn anhand der description
  • Der Skill läuft in derselben Session, im selben Kontext

Schritt 2 · Hintergrund

Progressive Disclosure: Skills kommen in drei Stufen

Eigene Darstellung nach agentskills.io, Farbweg HWZ-Shine (Rampe).

Sagen (Stichworte)

  • Discovery: beim Start kennt Claude nur Name und description aller Skills
  • Activation: passt eine Aufgabe oder kommt /zusammenfassen, wird die ganze SKILL.md geladen
  • Execution: Anweisungen ausführen, Skripte und Referenzen nur bei Bedarf
  • Darum kann man viele Skills haben, ohne den Kontext zu füllen
  • Einmal geladen, bleibt der Skill-Text im Kontext der Session

Schritt 3 · Problem

Der Skill liest alles in den Haupt-Kontext

Tippen

> /context

Terminal, schematisch

Context Usage
  Skills             ...
  Messages           ...   deutlich gewachsen
  Free space         ...   kleiner

Kernaussage

Der Skill sagt, wie gearbeitet wird. Gearbeitet wird aber im selben Kontext: 30 Notizen liegen jetzt in der Session, obwohl nur die Übersicht gebraucht wird.

Zeigen

  • /context neben den Wert aus Schritt 1 stellen
  • Auf Messages und Free space zeigen

Sagen (Stichworte)

  • Vergleich mit vorher: der Kontext ist voller
  • Jede gelesene Datei bleibt drin, bis zum /clear oder bis zur Verdichtung
  • Je voller der Kontext, desto ungenauer wird Claude bei späteren Aufgaben
  • Frage an die Gruppe: Wie könnte man lesen lassen, ohne dass es hier landet?
  • Antwort: eine Hilfskraft mit eigenem Schreibtisch. Das ist ein Subagent

Schritt 4 · Subagent

Einen Subagent per Prompt anlegen lassen

Tippen

> /clear
> Erstelle einen Subagent zusammenfasser in .claude/agents/. Er liest Notizen, gibt pro Datei einen Satz und am Schluss die drei wichtigsten Themen zurück. Er darf nur lesen: tools Read, Grep, Glob. Modell haiku.

Ergebnis: .claude/agents/zusammenfasser.md

---
name: zusammenfasser
description: Fasst mehrere Notizen zu einer Übersicht zusammen. Einsetzen, wenn viele Dateien gelesen werden müssen.
tools: Read, Grep, Glob
model: haiku
---

Lies die übergebenen Dateien vollständig.
Gib pro Datei einen Satz zurück, danach die drei wichtigsten Themen über alle Dateien.
Ändere keine Dateien.

Vor dem Kurs testen

  • Claude Code erkennt neue Dateien in .claude/agents/ laut Doku nach wenigen Sekunden ohne Neustart. Im Kurs-Setup bestätigen

Zeigen

  • Datei in Obsidian öffnen, Felder einzeln zeigen
  • Optional /agents tippen: zeigt seit v2.1.198 nur noch einen Hinweis, keinen Assistenten

Sagen (Stichworte)

  • Ein Subagent ist ebenfalls eine Markdown-Datei, diesmal in .claude/agents/
  • name und description sind Pflicht, wie beim Skill
  • tools: nur lesen. Er kann nichts kaputt machen
  • model: ein kleineres Modell genügt fürs Zusammenfassen
  • Der Text darunter ist seine Rollenbeschreibung, sein eigener Systemprompt

Schritt 4 · Subagent

Den Subagent aufrufen und beobachten

Tippen

> @agent-zusammenfasser Fasse die Notizen in Resources/ki-tools/ zusammen und schreibe das Ergebnis nach Resources/ki-tools/uebersicht.md.

Terminal, sinngemäss

zusammenfasser(Notizen in Resources/ki-tools zusammenfassen)
  ...  liest im eigenen Kontext
Write(Resources/ki-tools/uebersicht.md)

Währenddessen und danach

# Ctrl+B   laufenden Subagent in den Hintergrund schicken
> /tasks
> /context

Vor dem Kurs testen

  • Beim Tippen von @ fügt die Auswahl @"zusammenfasser (agent)" ein. Beide Schreibweisen ausprobieren
  • Ob 30 kurze Notizen lang genug laufen, um Ctrl+B und das Panel unter der Eingabe zu zeigen. Sonst mehr Dateien anlegen

Zeigen

  • Zeile zusammenfasser(…) im Terminal
  • Panel unter der Eingabe mit dem laufenden Subagent
  • /tasks: Liste mit Modell, Enter öffnet den Verlauf
  • Zum Schluss /context neben den Wert aus Schritt 3

Sagen (Stichworte)

  • Der Subagent liest alle 30 Dateien, aber in seinem eigenen Kontextfenster
  • Zurück kommt nur die Zusammenfassung
  • Schreiben macht die Haupt-Session, der Subagent darf ja nur lesen
  • /context: Messages kaum gewachsen. Das ist der ganze Trick
  • Alternative ohne @: «Nutze den zusammenfasser für …». Dann delegiert Claude in der Regel, aber nicht garantiert

Schritt 4 · Ablauf

Was bei der Delegation passiert

Die Haupt-Session erhält nur die Zusammenfassung, nicht die gelesenen Dateien. Eigene Darstellung, Farbweg HWZ-Shine.

Sagen (Stichworte)

  • Person gibt den Auftrag an die Haupt-Session
  • Die Haupt-Session schreibt selbst einen Auftrag an den Subagent
  • Der Subagent sieht das Gespräch davor nicht, nur diesen Auftrag und die CLAUDE.md
  • Er liest und verdichtet im eigenen Kontextfenster
  • Zurück kommt nur das Ergebnis. Daraus schreibt die Haupt-Session die Datei
  • Folge: der Auftrag an einen Subagent muss für sich allein verständlich sein

Schritt 5 · Kombination

Der Subagent nutzt den Skill

Tippen

> Ergänze im Subagent zusammenfasser das Feld skills mit dem Skill zusammenfassen.

Ergebnis: .claude/agents/zusammenfasser.md

---
name: zusammenfasser
description: Fasst mehrere Notizen zu einer Übersicht zusammen. Einsetzen, wenn viele Dateien gelesen werden müssen.
tools: Read, Grep, Glob
model: haiku
skills:
  - zusammenfassen
---

Lies die übergebenen Dateien und folge dem Skill zusammenfassen.
Ändere keine Dateien.

Tippen

> /clear
> @agent-zusammenfasser Fasse Resources/ki-tools/ zusammen.

Vor dem Kurs testen

  • Ob der Subagent den Hinweis im Skill «darfst du nicht schreiben, gib es zurück» befolgt und die Haupt-Session danach schreibt

Zeigen

  • Das neue Feld skills im Frontmatter
  • Das Organigramm von Schritt 1 erneut zeigen: Skill markdown am Subagent recherche

Sagen (Stichworte)

  • skills lädt den vollen Skill-Text beim Start in den Subagent, nicht nur die description
  • Arbeitsteilung: der Skill legt fest, wie. Der Subagent legt fest, wer und in welchem Kontext
  • Derselbe Skill funktioniert für die Session und für den Subagent
  • Subagents können selbst Subagents starten, bis drei Ebenen unter der Session. Dafür braucht der Subagent das Tool Agent in tools, unser zusammenfasser hat es bewusst nicht
  • Umgekehrt geht auch: ein Skill mit context: fork läuft in einem Subagent

Schritt 7 · Ausblick

Agent View: mehrere Sessions im Hintergrund

Tippen, in einer laufenden Session

# bei leerer Eingabe: Pfeiltaste links
> /bg Ordne die Notizen in Resources/ki-tools/ nach Kategorien.

Tippen, in der Shell

$ claude --bg "Ordne die Notizen in Resources/ki-tools/ nach Kategorien und schreibe die Liste nach Resources/ki-tools/kategorien.md"
$ claude agents

Tasten in Agent View

↑ ↓      Session wählen
Enter →  Session öffnen
←        bei leerer Eingabe zurück zur Übersicht
Space    Kurzansicht
Ctrl+X   Session stoppen
?        alle Tasten

Vor dem Kurs testen

  • Agent View ist Research Preview. Zeigt claude agents nur eine Liste und beendet sich, ist die Funktion nicht verfügbar: claude update
  • Jede Hintergrund-Session verbraucht Kontingent wie eine eigene Session. Im Pro-Plan sparsam zeigen

Zeigen

  • claude agents mit einer laufenden und einer fertigen Session

Sagen (Stichworte)

  • Subagent: Helfer innerhalb einer Session, liefert ein Ergebnis zurück
  • Hintergrund-Session: eine eigenständige Session für eine eigene Aufgabe
  • Agent View ist die Übersicht darüber: wer arbeitet, wer wartet, wer ist fertig
  • Zwei Sessions nie auf dieselben Dateien ansetzen

Schritt 7 · Ausblick

Workflows: viele Subagents nach einem Plan

Tippen

> /deep-research Welche Methoden zur persönlichen Wissensorganisation gibt es neben PARA, und wie unterscheiden sie sich?
> /workflows

In /workflows

↑ ↓      Phase oder Agent wählen
Enter →  hineinzoomen
Esc ←    zurück
p        pausieren
x        stoppen
s        als Befehl speichern  (.claude/workflows/)

Vor dem Kurs testen

  • Im Pro-Plan Workflows zuerst in /config unter «Dynamic workflows» einschalten
  • /deep-research braucht das WebSearch-Tool und verbraucht ein Vielfaches an Token. Lieber am Vortag laufen lassen und das Ergebnis zeigen

Zeigen

  • Freigabe-Dialog, dann /workflows mit Phasen und Agent-Zahlen

Sagen (Stichworte)

  • Ein Workflow ist ein Skript, das Claude schreibt und das viele Subagents steuert
  • Zwischenergebnisse liegen im Skript, nicht im Kontext. Zurück kommt nur der Bericht
  • /deep-research ist mitgeliefert: Websuche aus mehreren Winkeln, Gegenprüfung, Bericht mit Quellen
  • Eigene Workflows: «Nutze einen Workflow …» im Prompt
  • Während der Ausführung keine Rückfragen. Der Auftrag muss vorher klar sein

Schritt 7 · Ausblick

AGENTS.md: Anweisungen für jeden Agent

Fall 1: Ordner ohne CLAUDE.md

no CLAUDE.md found; AGENTS.md loaded: ~/PersonalOS/AGENTS.md

Fall 2: beides im Ordner, CLAUDE.md importiert

@AGENTS.md

## Nur für Claude Code
- Skills in .claude/skills/, Subagents in .claude/agents/

Vor dem Kurs testen

  • Hinweiszeile «AGENTS.md loaded» in einem Testordner ohne CLAUDE.md prüfen (ab v2.1.277)

Zeigen

  • Nur erklären, nicht live umbauen. Die Übung dazu steht im Modul AGENTS.md

Sagen (Stichworte)

  • AGENTS.md ist ein offener Standard, den viele Coding-Agents lesen, etwa Codex, Gemini CLI, Cursor
  • Claude Code liest sie seit v2.1.277, wenn im Ordner und darüber keine CLAUDE.md liegt
  • Liegt eine CLAUDE.md da, liest Claude Code nur diese. Dann @AGENTS.md oben in die CLAUDE.md
  • Ein Import spart keinen Kontext, der Text wird mitgeladen
  • Achtung Namensgleichheit: AGENTS.md beschreibt Regeln für den Agent, nicht Subagents

Schritt 8 · Zusammenfassung

Skill und Subagent im Vergleich

Eigene Darstellung nach code.claude.com/docs/en/skills und /sub-agents, Farbweg HWZ-Shine.

Sagen (Stichworte)

  • Skill: Anleitung, läuft im Haupt-Kontext, alles Gelesene bleibt dort
  • Subagent: Mitarbeiter mit eigenem Kontextfenster, nur das Ergebnis kommt zurück
  • Beides lässt sich kombinieren, in beide Richtungen
  • Faustregel für die Wahl: viel lesen, wenig zurückgeben, dann Subagent

Schritt 8 · Zusammenfassung

Skill legt fest, wie. Subagent legt fest, wer.

SkillSubagent
Ort.claude/skills/zusammenfassen/SKILL.md.claude/agents/zusammenfasser.md
Pflichtfeldername, description nach Standard; Claude Code verlangt nur die descriptionname, description
Aufruf/zusammenfassen oder passende Aufgabe@agent-zusammenfasser oder Name im Prompt
Kontextderselbe wie die Sessioneigenes Kontextfenster
Rückgabealles bleibt im Gesprächnur das Ergebnis
Grenzen setzendisallowed-toolstools, model

Hinweis zu /agents

Seit v2.1.198 zeigt /agents nur noch einen Hinweis statt eines Assistenten. Subagents entstehen per Prompt oder als Datei.

Sagen (Stichworte)

  • Skill = wie: Anleitung im selben Kontext
  • Subagent = wer: eigener Kontext, nur das Ergebnis zurück
  • Wiederkehrender Ablauf, wenig Lesestoff: Skill
  • Viel lesen, wenig zurückgeben, oder eine Rolle mit klaren Grenzen: Subagent
  • Kurze Einzelaufgabe oder Aufgabe, die das bisherige Gespräch braucht: kein Subagent

Überleitung

  • Zur Übung im Modul Subagents und Workflows: eigenen ablage-pruefer anlegen, nur lesen
